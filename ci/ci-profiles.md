# CI profiles

Default PR checks run Flutter 3.38.5 on each supported platform. Native static
analysis, unit tests and one publish dry-run share a runner on that same version.
Analysis errors and warnings fail the job; existing informational notices do not.
Pub scoring remains in the weekly suite. The Android example build checks 16 KB alignment using its APK
outputs. Documentation artifacts are generated by the release workflow.

A normal PR allocates 14 runners including the permission check, with three macOS
workers. Apple packaging changes add two macOS workers, making 16 runners total.
GitHub also displays skipped optional jobs; these do not allocate runners.

Apple app/Archive linkage checks, source-package consumer builds and the iOS
example build run when the PR changes Apple/native sources, package manifests,
package layout, the example, SwiftPM fixtures or CI tooling. The selection lives
in `check_apple_changes.py`. Renames include both old and new paths. If change
history cannot be read, packaging checks run conservatively. Each packaging
build is limited to 20 minutes and its worker to 60 minutes.

Use the existing `run_test_weekly_latest_stable.yml` manual workflow on the target
ref and select `suite`:

| Suite | Checks |
| --- | --- |
| `latest-stable` | Existing weekly latest-stable coverage; also used by the unchanged schedule |
| `full-compatibility` | All preserved Flutter 3.16/3.24.5/3.38.5 and host combinations, source consumers, and Apple package checks |
| `legacy-ios` | Only Flutter 3.16 iOS runtime compatibility |

The full suite calls `run_test.yml` with `full_compatibility=true`; it preserves all
18 original Apple check groups and Windows-host Android builds. Latest-stable
SwiftPM consumers remain in the weekly/full suites. Manual suites skip the regular
weekly jobs and use separate concurrency groups.

Run the full suite for broad SDK adaptations or compatibility validation. For a
release, use results from the commit being released rather than repeating a
successful check on identical code. The release workflow and post-release git/pub
consumer verification retain their existing behavior.

Local policy checks:

```sh
ruby ci/check_apple_ci.rb
python3 -m unittest ci/test_check_apple_changes.py ci/test_flutter_vm_service_watchdog.py ci/test_ios_integration_startup_retry.py
```
